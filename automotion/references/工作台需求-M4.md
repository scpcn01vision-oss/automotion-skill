# 工作台需求（M4）

> 日期：2026-08-09
> 状态：定稿（2026-08-10 交付实施；2026-08-13 skill 封装收录为 references）
> 用途：M4 工作台开发的需求依据。用户审核修改后，作为开发规格交给开发（分支对话）执行。
> 前置：M1-M3 已完成（镜头库 122、数据模型、匹配机制 MatchResult + Top5）。

---

## 1. 目标

工作台 = **人工定稿工具**（浏览器网页）。输入 M3 匹配结果（每段 Top 5 候选 + 理由），人工完成两件事：

1. **分镜定稿**：为每段选定镜头 + 调整参数
2. **字幕样式定稿**：设定全片统一的字幕样式

产出：项目侧 `storyboard.json`（lensId / params / subtitleStyle），供 M5 整片预览与导出消费。

**不是**：自动选镜工具（选镜是人工决策，系统只给候选和理由）、整片合成工具（那是 M5）。

---

## 2. 整体流程

```
项目文案 + 录音（示例项目，项目侧）
  → 分段 + 转录（第一步产物）
  → M3 匹配：每段 Top 5 候选 + reason（MatchResult）
  → 工作台环节一：分镜定稿（选镜头 + 调参数 + 保存）
  → 工作台环节二：字幕样式（调整 + 保存）
  → storyboard.json（项目侧，权威）
  → M5：整片预览 / 导出
```

工作台与 Remotion 解耦：工作台只负责「段 → 镜头 → 参数 + 字幕样式」，不参与整片组装。

---

## 3. 数据输入

| 数据 | 来源 | 用途 |
|---|---|---|
| MatchResult | M3 输出（候选 JSON，含 `core` + `top5[{lensId, reason}]` + 可写 `chosen`） | 右栏推荐区展示 |
| 段画像 | 项目侧（角色牌 + 内容牌 + 段原文） | 左栏展示段信息；辅助人工判断 |
| registry（122 镜头） | `shared/registry.json`（id / 中文名 / 分组 / props schema / scenes / usage） | 镜头库列表 + 参数表单生成 |
| storyboard | 项目侧（可空：首次由工作台从段画像生成待定稿骨架） | 读已有定稿继续编辑；保存写回 |

---

## 4. 环节一：分镜定稿（三栏布局）

### 4.1 左栏：段列表

- 每段一行：序号、段文本摘要、定稿状态（已选镜头名 / 未定稿）
- 点击选中当前段，当前段高亮
- 段多时滚动条浏览
- 底部固定操作条（滚动时不跑）：「保存当前段」「进入字幕设定」

### 4.2 中栏：镜头预览 + 参数表单

- **预览**：@remotion/player 实时播放当前选中镜头（用当前参数渲染），非真实时长；与右栏悬浮窗共用同一播放入口
- **参数表单**：按所选镜头的 props schema 自动生成，支持基础类型（string/number/boolean）输入、**数组/嵌套结构列表行编辑**（如卡片 3 张→2 张：行列表增/删/改）、深层未知类型 JSON 文本兜底；修改参数即时更新预览；保存时按类型正确转换（number/boolean 不落成字符串）
- 未选镜头时显示占位提示（「请从右侧选择镜头」）
- 中栏随右栏伸缩等比放大/缩小

### 4.3 右栏：推荐区 + 镜头库

- **推荐区（置顶）**：当前段 Top 5 候选，全部展示不折叠；每条显示镜头名 + reason（一句话理由）+ 「选用」按钮；已有 `chosen` 的段高亮已选
- **镜头库**：全部 122 镜头，按分组折叠展示；条目含中文名；**鼠标移到镜头条目 → 弹出悬浮窗播放该镜头动效**（@remotion/player 小窗，默认参数、循环播放），移开消失；点击条目 = 选用该镜头
- **无延迟要求（硬性）**：镜头库全程只调本地数据（registry / 镜头代码 / 播放包，无网络请求）；悬浮窗从 hover 到出现 ≤100ms、动效立即开始播放（不等待模块加载；不做首帧预渲染——避免 122 镜头后台渲染开销，实测不足再加）
- 右栏可伸缩（收起后只留推荐区或全收起，中栏放大）

### 4.4 关键交互

- **换镜头自动填参**：点击任何镜头（推荐区或镜头库）→ 中栏参数表单刷新为该镜头 props 的默认值 → 预览同步切换
- **自动预选 Top 1**：打开工作台或切换段时，该段未定稿则自动选中匹配结果 Top 1 镜头（显示预览 + 参数表单），用户无需手动点选最高优先级镜头；已定稿的段自动加载已保存的镜头与参数
- **防重复提示**：若选用镜头与前面 <5 段内已用镜头重复，右栏给出提示（不阻止，仅提示——符合 M3「间隔 ≥5 段允许复用」）
- **保存当前段**：把当前段的 `lensId` + `params` 写入 storyboard；保存一次更新一次，无向导
- **复杂参数调整回 Codex 对话**：工作台不做 AI 对话；布局/结构级调整（如卡片数量、嵌套内容）可保存后回到 Codex 对话用提示词改 storyboard.json，再点「重新加载」拉取
- **手动重新加载**：中栏顶部「重新加载」按钮，重新拉取 `/api/storyboard`（丢弃未保存编辑，用户主动触发）

---

## 5. 环节二：字幕样式（两栏布局）

- **左栏（大部分）**：预览区——展示「第一个镜头稳定后的画面」作为字幕效果底图，叠加字幕文字（模拟真实字幕效果）
- **右栏**：字幕参数调整区：
  - 字号 / 字体 / 颜色 / 描边色 / 描边宽 / 背景色 / 位置（底部/顶部/居中）/ 对齐 / 字间距
- 底部按钮：「返回上一步」（回环节一）、「确定当前设置」（二次确认后保存）
- **保存**：写入 `storyboard.meta.subtitleStyle`（全片统一）

> 字幕文本与时间码来自第一步转录，本环节**只定样式**，不做时间轴拖拽编辑。

---

## 6. 数据流与文件

- **读**：MatchResult（项目侧或 out/，gitignored）+ 段画像（项目侧）+ registry（仓库）
- **写**：`storyboard.json`（项目侧，不进仓库；结构遵循 `shared/types.ts` 的 Storyboard schema）
- **预览缓存**：`RENDER_VERSION | lensId | params | frames`，命中直接返回，避免重复渲染
- **首次进入**：若项目侧无 storyboard，工作台按段画像生成待定稿骨架（每段 text/keywords/durationSec 就位，lensId 空）

## 7. 技术方案（待确认，不影响需求本身）

- client：React + Vite（浏览器应用）
- 预览（中栏 + 右栏悬浮窗）：@remotion/player 播放镜头动效，共用一个播放入口（复用 `lenses/Root.preview.tsx` 或建精简入口）；悬浮窗只对当前 hover 镜头启动播放、移开销毁
- **无延迟保障**：工作台启动即后台预热播放包（镜头模块全部加载，hover 时组件已就绪）；悬浮窗 UI 即时弹出、播放器即时启动，不等数据；不做首帧预渲染
- server：Express——浏览器无法直接写本地文件，需提供数据 API（读 MatchResult / 段画像 / storyboard，写 storyboard）；渲染相关（@remotion/renderer）M4 暂不需要，留给 M5
- 端口：client 5173 / server 3004（独立端口）；3003 保留给 Remotion Studio

## 8. 验收标准（M4 完成判据）

1. **换镜头自动填参**：点击镜头 → 中栏参数表单刷新为该镜头默认值
2. **保存生效**：点「保存当前段」→ storyboard.json 对应段更新（lensId + params）
3. **字幕保存**：字幕样式保存 → storyboard.meta.subtitleStyle 更新
4. **示例项目端到端**：用示例项目段画像 + 匹配结果走完「候选 → 选镜 → 调参 → 保存 → 预览」全流程
5. **hover 无延迟动效预览**：镜头库 hover 弹出悬浮窗播放动效（默认参数循环），移开消失；悬浮窗 ≤100ms 出现、动效立即开始播放（模块已预热）、播放不卡顿（全程本地数据、无网络等待）
6. **数组行编辑**：选带数组参数的镜头（如 CardFlipReveal cards）→ 行列表增/删/改 → 保存后 storyboard.json 对应 `params` 数量与字段正确
7. **类型转换**：number 参数保存后为数字（非字符串）
8. **手动刷新**：Codex 对话改 storyboard.json → 工作台点「重新加载」→ 显示新参数
9. **单镜头预览出错不白屏**：任一镜头预览失败只显示占位提示，工作台其余功能可用

---

## 9. 明确不做（M4 范围外）

- 整片组装 / 预览 / 导出（M5）
- BGM
- 字幕时间轴拖拽编辑
- LLM 对话选镜头（候选由 M3 生成，工作台只展示与人工选择）
- 多视觉风格
- 项目数据进仓库（storyboard 等全在项目侧）
