# 字幕切分规范（M5 · v4）

> 生成：2026-08-11 ｜ 用途：M5 转录工具的字幕切分实现依据
> 依据：013 v6 实际字幕（字幕_v6.srt，283 条）规律 + 用户两轮逐条反馈修正（2026-08-11）
> 配套：`013\stage2_pipeline.py`（whisper 转录 → 对齐 → 切分 → SRT 的 v6 参考实现）
> 实现：`scripts/transcribe.py`（split_subtitles / split_long）

## 核心原则

**一条字幕 = 口语的一次停顿 / 一个语义完整的语块**。切分跟随口语的节拍与气口，不按字数机械切。

**v4 核心：语义分割优先于机械规则**。长度上限只是「别超」的约束，不是「数到 N 硬切」的触发器——超长时在句内找**语义边界**（副词/动词短语/介宾/主谓）切，而不是数到第 N 个字切。

## 规则

### 1. 停顿驱动

切点 = 标点（逗号/句号/问号/分号）、介词/连接词前、插入语前后、对偶短句。

### 2. 单条 ≤ 18 汉字

- **语义优先**：有明确语义边界（副词转折/动宾分界/介宾短语）即使 18 内也切（如「传统公司通过内部的协调机制 / 相比于市场」）
- 超 18 时在句内找语义边界切，**不数到 18 硬切**
- 长度判定用**汉字数**（英文/数字不计入 18 上限）
- 语义切点分级：
  - **强切点**（不论长短都切）：副词（现在/原本/基本/大抵/完全/可能/根本/尽量/不再/甚至…）、动宾分界（贡献/解决/纳入/转向/相比…）、动词切后（写进了/创造了/做到/叫）
  - **弱切点**（仅超 18 用）：句内介词/系词（通过/用/在/是/被/把/来/为/从/就/都/也…），避免过度切分

### 3. 问答分开

问号后答案另起一条，不合并（避免剧透）。

### 4. 词跟语义走

切完每条语义必须完整；副词（现在/原本/基本上/大抵/完全/可能/根本/甚至）跟它修饰的谓语走，禁止以名词/副词收尾的不完整条。

### 5. 主谓之间可切

主语 | 谓语 两侧各自完整即可（如「可以说FFmpeg | 是现在互联网视频的核心基础设施」）。

### 6. 连接词「和/与」不留在句首

### 7. 无顿号的超长句（「的」最后手段）

只有实在找不到语义边界时才在「的」字前切，允许后句以「的」开头（如「之间的平衡…」）。**「的」不是常规切点**——名词短语（北京市的正式政策文件 / 数千亿万亿的商业价值 / FFmpeg的开源项目）整体不拆。

### 8. 短句/插入语/口头语独立成条

序号词（第一/第二/第一种TaaS）、口头语（好/说实话/换句话说/你可能会问）、连接语（那现在）独立成条。

### 9. 顿号分组

并列项（术语清单/列举）按顿号分组成视觉 ≤18/组的块（英文/数字 2 半角 ≈ 1 汉字）；组内不拆专有名词。

### 10. 书名号与引号

- 书名号**内容**整体不切，但书名号外可切（「北京市发改委联合多部门发布了」+《…》）
- 后引号归引文（绝不单独成为新句开头）；引号内长引文允许语义切
- 专有名词（开源贡献度评价体系 / Token / FFmpeg / Agentic AI）不拆

## 避免的缺陷

- 不切断书名号、不拆专有名词、不把词错误并入前句、引号拆不过碎、后引号不单独起句
- 「的」不作为常规切点（除非无任何语义边界）

## 输出格式（v7 Subtitles schema）

```ts
{
  entries: [
    { index: 1, text: '中国有句古话', startSec: 0.18, endSec: 0.94, segmentId: 'seg-01' },
    ...
  ],
  style: { fontSize: 48, color: '#2c2416', position: 'bottom', ... }  // 工作台保存的 subtitleStyle
}
```

- 时间轴来源：whisper 词级时间戳对齐文案后，每条字幕在词级时间戳中定位起止
- 条间基本连续（上条 end ≈ 下条 start）
- 产物写项目侧，不进工具仓库
