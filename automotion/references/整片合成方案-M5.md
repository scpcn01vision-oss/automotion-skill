**目标**：文案 + 录音 → 整片（1920×1080、30fps、mp4、自然时长、无 BGM），预览与导出都带口播声音。

## 1. 时间轴基准：音频优先

- **音频真实时长是 Composition 总时长的唯一基准**：`durationInFrames = round(audioDurationSec × 30)`
- `transcribe.py` 用 `wave` 直接读 `full.wav` 的帧数/采样率 → 写入 `subtitles.json` 的 `meta.audioDurationSec`
- 段时长总和可以小于音频时长（允许尾音余量，最后一句词结束到音频结束的静音），差值不是 bug

## 2. 段时长精度（seg-04/06/15 的教训）

- `durationSec` 必须来自真实转录时间跨度（段内字幕最小 start → 最大 end），更新阈值用 `0.001s`——之前 `0.2s` 阈值漏掉了 0.2s 内的偏差，导致累计错位
- `WholeVideo` 帧边界用**逐段 round**：`startFrame = round(cumSec×30)`、`endFrame = round((cumSec+durationSec)×30)`、`dur = endFrame − startFrame`；不能用 `cursor += round(durationSec×30)`（会产生累积漂移）

## 3. 音频路由：单一数据源，不复制资产

- 音频只在项目目录存一份（`V7_PROJECT_DIR/full.wav`），不进仓库、不进产物
- server（3004）提供 `GET /api/audio/:file`，从 `PROJECT_DIR` 读取；`basename` 防目录穿越；CORS 全开；支持 Range（浏览器/mediabunny 渐进式加载需要）
- `<Audio src>` 必须用 **http 地址**：浏览器无法加载本地绝对路径（`E:\...` 会被当未知协议），只有 http 才能预览出声
- 渲染时 Remotion 也能访问该 http 地址（server 需常驻，`dev:whole` 已包含）

## 4. `<Audio>` 组件位置（本次核心教训）

- **必须放在视频组件内部**（`WholeVideo` 的 `<AbsoluteFill>` 里），不能放在 `<Composition>` 的 children——Remotion 4.x 的 `Composition` 只渲染 `component`，children 被直接丢弃
- 症状：时间轴无录音轨道、页面 `<audio>` 元素数量为 0、无报错；渲染产物会得到**静音音轨**
- `WholeVideo` 接受可选 `audioSrc` prop，有才渲染，保持通用性

## 5. 验证流程（端到端）

1. `python scripts/transcribe.py --skip-transcribe` → 修复 `durationSec` + 写入音频元数据
2. 数据核对：段总和 vs `audioDurationSec`（差值为尾音余量）
3. 预览：`npm run dev:whole`（工作台 5173 + 整片 3003），时间轴应出现 `full.wav` 轨道，刷新后能听到口播
4. 渲染验证：小范围渲染 + **响度检测**（`ffmpeg volumedetect`）——不能只看有没有音轨，`-91dB` 是静音轨道不算有声音，正常口播应在 `mean -20dB` 左右
