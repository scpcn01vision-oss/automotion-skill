# 「文案 → 参数」自动映射规律（M4 沉淀）

> 日期：2026-08-10
> 用途：v7 skill 生成其他项目 `storyboard.json` 参数时的参考依据（对应 M3 匹配流程第 6 步「参数生成」；skill 阶段 6 封装时打包为 references）。
> 样本：示例项目的 32 段「理想镜头参考答案」（项目侧，不进仓库）+ `shared/registry.json` 的 props schema。
> 边界：**工作台不做 AI，不生成参数**。生成动作由 skill/流程完成，工作台只展示与预览、人工微调后保存。

---

## 1. 通用原则（先于具体镜头）

1. **只填文案/段画像里真实出现的内容，不发明**。字段缺信息就留空/省略，让组件用默认值。
2. **数值与原文精确一致**：日期（7月21日）、条款号（第五条）、金额（520万）照抄；单位单独放 `unit`/`label` 类字段。
3. **结构跟着语义走**：
   - 引用 → 拆成 机关/文件/条款号/原句（`RedHeadFileQuote` 系）
   - 对比 → 双方各占 `sceneA`/`sceneB` 或 `titleA`/`titleB`
   - 列举 → 数组字段，条目数 = 列举项数（`cards`/`rows`/`words`/`sidebarItems`）
   - 设问 → `query`/`placeholder` 放问题，`summary`/`scene` 放回答
   - 情绪/结论 → 短字段（`title`/`highlight`/`wordmark`/`pillText`）
4. **params 类型必须与 registry props 对齐**：number 是数字、boolean 是布尔，数组用数组字面量（保存时工作台按类型转换）。
5. **动画/帧类字段（`beats`/`start`/`end`/`zeroFrom` 等）按内容量给估算值即可**，工作台可人工调整；真实时长由转录对齐决定（`durationSec`/`phraseRange` 不在此表）。
6. 生成后必须过 `shared/types.ts` 的 `isStoryboard` 校验。

## 3. 使用方式

1. 新项目完成分段（段画像：摘要/角色牌/内容牌）与 M3 匹配（Top5 + reason）后，按上表为每段选定镜头填参。
2. 以示例项目参考答案为格式样板：每段一个 `lensId` + `params` JSON，写回项目侧 `storyboard.json`。
3. 工作台读取展示；人工在行编辑/JSON 兜底中微调后保存。
4. 若某镜头在真实项目中参数始终填不准 → **修订本表对应的映射规律**（定位问题在规律，不在工作台补丁）。

## 3.5 口播对齐（内容 → 时间映射，2026-08-14 新增）

**原则**：镜头参数里与口播文案有对应关系的内容项（逐词/逐项展示、事件触发），**默认自动对齐口播时间**——画面事件发生在口播念到对应内容（或用户指定的文案）的时刻；用户手动指定只是对自动化的补充。

**时间数据源**：`transcript.json` 的 `phrases`（文案词级时间戳，整片秒；未匹配词有兜底时长）。字幕文件只有句级起止，定位不到词，必须查转录文件。

**换算**：段内秒 = 词整片秒 − 段起始整片秒（段起始 = 前面各段 `durationSec` 之和，与整片 `WholeVideo` 的 cumSec 一致）。

**写法**：内容项对应镜头的 `params` 增加与内容项一一对应的时刻数组：

- 逐项展示类（如 `BeatStepListThemeCycle.words` ↔ `cueSec: number[]`）：`cueSec[i]` = 第 i 个内容项进入选中位的段内秒；首项通常为 0（铺垫期起始态）
- 单事件类（如 mask 放大、揭幕、收束）：事件绑定时刻（`revealAtSec` 等），开始/完成语义按用户指令

**流程**：填参时用转录词级时间戳查每个内容项对应文案的开始秒 → 换算段内秒 → 写入 params。组件提供时刻表模式（如 `cueSec`），未提供时保持原拍长/弹性行为。

**示例项目（seg-04）**：`words` 8 个术语 ↔ `cueSec: [0, 2.62, 3.78, 4.60, 5.22, 6.24, 7.10, 7.66]`（段内秒，查自口播词级时间戳：Agentic AI 40.68 / Harness 41.72 / AI OS 42.88 / OPC 43.70 / Token经济 44.32 / 银河算廊 45.34 / AIP 46.20 / 以模治模 46.76，段起点 39.10s）。

**已覆盖镜头**（2026-08-14 批量接入）：
- 逐项 `cueSec`：BeatStepListThemeCycle / CelFlashStomp / GridWaveFlip / PaperTitleCard / CardFlipReveal / PopupBookRise / StreamResponse / SkeletonReveal / WordRelayFilmstrip
- 单事件 `revealAtSec`：TextAsMask / MarkerUnderlineTitle / MaskingTapeSlap / RedHeadFileQuote / VersusSlam / BarnDoorSplit / HashtagToPillMaterialize / InkBleedReveal / SplitTextStagger / TypewriterErrorRetype / InvisibleCut / IconFlipBloomLogo / LightLeakBurn / TitleDemoteToLabel / GradientWordSweep / HalationBloom / ReticleLockOn / DrawSvgTrace / SlideSpotlightPan / LineUnfoldPanel / GlowWakeSleepPanel / ImpactBurstKit / MagicianCardFlourish


**不做对齐的判断标准**（避免硬套）：
1. 口播没有逐项锚点（如只笼统说"三个机会"不逐字念）→ 不加 cueSec
2. 动画是连续滚动/展示（波形、滚数）→ 无单点事件锚定
3. 镜头 A→B 内容顺序与口播叙述顺序错位 → 锚定会加剧错位
4. 流程型动画（面板降临/输入/蒸发一体）→ 无对应口播事件

## 4. 明确不做

- 不做机械提取脚本（语义填参由 skill 完成；本表只是参考规律）
- 不把示例项目数据或参考答案带入仓库
- 不覆盖组件默认值：storyboard 只写需要覆盖的字段
