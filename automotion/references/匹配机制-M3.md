# 匹配机制（M3）——定稿 2026-08-09

> 目的：automotion-v7 从镜头库为每个段选出候选镜头（Top 5），人工定稿。
> 依据：2026-08-09 与用户的机制讨论共识；示例项目的 32 段参考答案为校准样本。

## 已拍板约束

- **无准入 / 无排除 / 无禁入**：任何镜头都可被匹配，不做预筛。
- **标签是排序信号，不是排除条件**：段的角色/内容牌命中镜头标签 → 排序靠前；命中不了不排除。
- **语义优先**：AI 先理解段的实质（一句话核心含义），再与镜头的「使用场景描述」语义对齐——不是关键词匹配。提炼核心含义是实现语义化的一种方法，本质是避免机械关键词匹配。
- **人工定稿**：工作台保存式交互（镜头/字幕各有保存按钮），整片预览验收为人工。

## 输入

- storyboard.json 的 segments：text + summary + role（角色牌）+ features（内容牌）
- 镜头定位库：`docs/lens-scenes-draft.md`（场景标签 + 使用场景描述，由人定义镜头定位）
- 上下文：本段及前后段的镜头安排（防重复）

## 匹配流程

1. **语义理解**：AI 用一句话写出这段的实质（核心含义）。
2. **语义对齐**：拿核心含义与每个镜头的使用场景描述对齐（语义，不是关键词命中）。
3. **排序**：段的角色/内容牌命中镜头标签 → 加权靠前（标签 = 排序信号）。
4. **防重复**：同一镜头间隔 <5 段排除；间隔 ≥5 段允许复用。
5. **输出 Top 5 候选**，全部展示不折叠；匹配时可渲染候选预览辅助判断（质量优先、速度放宽）。
6. **参数生成**：镜头人工定稿后，按选定镜头的 props 结构生成参数。

## 驳回反馈

- 镜头被否 → 修正该镜头的使用场景描述 / 标签本身；**不维护黑名单**。
- 定位库是匹配质量的源头：驳回是"定位写错/写模糊"的反馈信号，修定位而不是绕开镜头。

## 校准

- 示例项目的 32 段参考答案作为**内部测试集**：匹配时不看，用于验证命中率。
- 命中标准：参考答案镜头出现在该段 Top 5 内。
- 2026-08-09 校准演练：32/32 命中（含局限说明——参考答案为近期人工定稿，命中率高属预期；演练价值在于暴露定位库问题）。
